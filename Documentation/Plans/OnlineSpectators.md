# Online spectator implementation plan

Let invited viewers watch a live Counterattack match while the two managers keep control of their teams. Build on the existing guest rendering path and keep the spectator lifecycle independent of online save and resume.

## Player and viewer flow

1. The host shares one **Match Code** for the session. Keep **Copy Match Code** in the host lobby and in the host's local Online Match panel in Room. Opening this panel or copying the code during play must leave the match clock running. **Allow spectators** defaults to on. Show both managers whether viewing is enabled and how many viewers are connected. Let the host turn viewing off before or during the match.
2. Guests use **Online → Join** and enter the Match Code. After validation, show **Join as Away** while a new match's Away seat is free and **Spectate** while viewing is enabled and there is capacity. The host grants the first valid Away request atomically. Only the two assigned managers advance to the next setup scenes. A spectator who joins early waits for Room without seeing setup or Draft. Later spectators use the same code to join the live match. Show clear feedback for invalid or closed sessions, full capacity, incompatible builds, and connection failures.
3. The viewer sees the live pitch, lineups, score, clock, public events and final result. They control their own camera and use a white pointer to hover and open public previews. Their pointer and inspection activity stay local. Provide **Leave** through the authored menu.
4. Start with a cap of **two spectators** in addition to the two managers. Treat the cap as a release setting to validate on paired builds. Keep the first release focused on live, code-based viewing. Public discovery, chat, replays, delayed broadcasts and seat takeover are future work.

## 1. Admit viewers without taking a player seat

- Keep the current two-seat manager lobby. Prototype a separate EOS watch lobby owned by the same host, with presence disabled and its own internal lobby ID, socket or channel, capacity and lifecycle. Resolve the shared Match Code even when the EOS manager lobby is full. Verify simultaneous lobby ownership, late joins and cleanup with the packaged Windows and macOS clients before building the interface. If the current deployment cannot support the separate lobby, resolve the transport design before exposing Spectate. [EOS lobby permissions](https://dev.epicgames.com/docs/epic-online-services/multiplayer/lobbies-and-sessions/lobby-interface/lobby-interface-reference)
- Treat lookup and role authorization as separate steps. The host's game automatically verifies the EOS identity, Match Code, compatibility and capacity before granting the requested role. Publish only a lookup value derived from a sufficiently random Match Code and verify the full code during the handshake. Bind each admission to the authenticated peer, current match and role. Once Away is assigned, reserve it for that manager on reconnect. Rate-limit admission, expire pending requests and reject duplicate, stale and excess requests. Only approved viewers receive public match state or occupy a viewer seat. Verify that unapproved EOS members cannot keep valid guests out before enabling viewing by default. Turning viewing off disconnects viewers and disables new viewer admission. The Match Code stays valid for manager reconnect until the session ends.
- When save/resume is available, keep the original authenticated Home and Away identities reserved. A different guest can use the same Match Code to spectate if viewing is enabled. Only the original Away manager can use the manager role.
- Preserve the manager connection and its recovery flow. Introduce an independent spectator connection table and dispatch using the authenticated sender and channel. Reject every gameplay or shared-control request from viewers, including pause, rolls, substitutions, readiness and saves, before it reaches the gameplay command handler. Viewer join, acknowledgement, disconnect or retry cannot hold or resume match play. Start from [OnlineFrontendSession.cs](../../Assets/Scripts/Online/OnlineFrontendSession.cs), [OnlineMatchProtocol.cs](../../Assets/Scripts/Online/OnlineMatchProtocol.cs) and [EOSStandalonePacketProbe.cs](../../Assets/Scripts/Online/EOSStandaloneProof/EOSStandalonePacketProbe.cs).

## 2. Render a public view in Room

- Add the role chooser to the existing Online submenu as an authored player-card-style panel, with the available roles as menu items. Reuse the submenu's typography, colors, selection states and back navigation.
- Add an explicit spectator startup role with no local team. Reuse replica rendering for the board, ball, tokens, clock and scoreboard. Audit `IsGuest` and team assumptions before sharing code. Limit spectator pointer input over the pitch to hovering and opening public previews. Never send pointer position, hover or preview state over the network. Keep local camera and menu input available. Spectator bootstrapping must avoid authority initialization, gameplay input, manager prompts and match-save writes. Author status and spectator menu controls in scenes or prefabs. [OnlineRoomSession.cs](../../Assets/Scripts/Online/OnlineRoomSession.cs) · [OnlineRoomStartup.cs](../../Assets/Scripts/Online/OnlineRoomStartup.cs) · [OnlineGroundPassBoard.cs](../../Assets/Scripts/Online/OnlineGroundPassBoard.cs)
- Build a spectator publication with an explicit list of public fields, including committed positions and animations, visible roster and kit data, score, clock, public announcements and final result. Keep legal actions, uncommitted movement and target previews, cursors, private selections, setup and Draft decisions, and account or save metadata out of spectator payloads. Audit nested pose and event data as well as top-level fields. Reveal outcomes only when they become public to both teams.
- Send a complete public snapshot to late joiners, then ordered updates using the match identity and publication sequence. Viewer recovery requests a fresh snapshot and drops obsolete updates without affecting managers. Use separate bounded queues and rate limits, replace superseded snapshots for slow viewers, and prioritize manager traffic. When the host shuts down, show a clear end-of-session state and release both lobby and transport resources.
- Apply the compatibility rules in [CONTRIBUTING.md](../../CONTRIBUTING.md). Version the spectator handshake and publication. If the implementation also changes required manager messages, bump the affected protocol and verify existing two-player sessions with spectators disabled. Keep spectator work independent of any future saved-match loading.

- [ ] Run packaged Windows and macOS clients with two managers and one viewer, then repeat at the spectator cap. Exercise cross-network joins, direct and relay paths where available, a slow viewer, disconnect and rejoin, and clean shutdown. Compare manager command latency, host frame time and outbound traffic with zero viewers and at the cap. Base any cap increase on those measurements.
