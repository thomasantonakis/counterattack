# Online spectator implementation plan

Let invited viewers watch a live Counterattack match while the two managers keep control of their teams. Build on the existing guest rendering path and keep the spectator lifecycle independent of online save and resume.

## Player and viewer flow

1. The host opts in to **Allow spectators**. Once the match reaches Room, the host can copy a separate **Watch Code**. Show both managers that spectating is enabled and how many viewers are connected.
2. An invited viewer selects **Online → Watch**, enters the code, and joins the current match in progress. Show clear feedback for an invalid or closed invite, a full lobby, an incompatible build, and connection failure.
3. The viewer sees the live pitch, lineups, score, clock, public events and final result. They can use their own camera and inspect visible player information. Provide **Leave** through the authored menu. Offer the host the ability to stop spectating and close the watch lobby during the match.
4. Start with a cap of **two spectators** in addition to the two managers. Treat the cap as a release setting to validate on paired builds. Keep the first release focused on live, code-based viewing. Public discovery, chat, replays, delayed broadcasts and seat takeover are future work.

## 1. Admit viewers without taking a player seat

- Keep the current two-seat manager lobby. Prototype a separate EOS watch lobby owned by the same host, with presence disabled and its own code, socket or channel, capacity and lifecycle. Verify simultaneous lobby ownership, late joins and cleanup with the packaged Windows and macOS clients before building the interface. If the current deployment cannot support the separate lobby, resolve the transport design before exposing Watch. [EOS lobby permissions](https://dev.epicgames.com/docs/epic-online-services/multiplayer/lobbies-and-sessions/lobby-interface/lobby-interface-reference)
- Treat lobby discovery and watch authorization as separate steps. Validate the invite on the host after EOS authentication and match/compatibility checks. If discovery uses a searchable attribute, publish only a lookup value derived from a sufficiently random watch code and verify the full code during the handshake. Only the host can grant the viewer role. Bind the role to the authenticated peer and current match. Handle duplicate joins, simultaneous requests for the last seat, and stale invites with a bounded admission timeout. Invalidate invites and disconnect viewers when the host turns watching off or ends the session.
- Preserve the manager connection and its recovery flow. Introduce an independent spectator connection table and dispatch using the authenticated sender and channel. Reject every gameplay or shared-control request from viewers, including pause, rolls, substitutions, readiness and saves, before it reaches the gameplay command handler. Viewer join, acknowledgement, disconnect or retry cannot hold or resume match play. Start from [OnlineFrontendSession.cs](../../Assets/Scripts/Online/OnlineFrontendSession.cs), [OnlineMatchProtocol.cs](../../Assets/Scripts/Online/OnlineMatchProtocol.cs) and [EOSStandalonePacketProbe.cs](../../Assets/Scripts/Online/EOSStandaloneProof/EOSStandalonePacketProbe.cs).

## 2. Render a public view in Room

- Add an explicit spectator startup role with no local team. Reuse replica rendering for the board, ball, tokens, clock and scoreboard. Audit `IsGuest` and team assumptions before sharing code. Spectator bootstrapping must avoid authority initialization, gameplay input, manager prompts and match-save writes. Author **Watch**, status and spectator menu controls in scenes or prefabs. Keep local camera and inspection available. [OnlineRoomSession.cs](../../Assets/Scripts/Online/OnlineRoomSession.cs) · [OnlineRoomStartup.cs](../../Assets/Scripts/Online/OnlineRoomStartup.cs) · [OnlineGroundPassBoard.cs](../../Assets/Scripts/Online/OnlineGroundPassBoard.cs)
- Build a spectator publication with an explicit list of public fields, including committed positions and animations, visible roster and kit data, score, clock, public announcements and final result. Keep legal actions, uncommitted movement and target previews, cursors, private selections, setup and Draft decisions, and account or save metadata out of spectator payloads. Audit nested pose and event data as well as top-level fields. Reveal outcomes only when they become public to both teams.
- Send a complete public snapshot to late joiners, then ordered updates using the match identity and publication sequence. Viewer recovery requests a fresh snapshot and drops obsolete updates without affecting managers. Use separate bounded queues and rate limits, replace superseded snapshots for slow viewers, and prioritize manager traffic. When the host shuts down, show a clear end-of-session state and release both lobby and transport resources.
- Apply the compatibility rules in [CONTRIBUTING.md](../../CONTRIBUTING.md). Version the spectator handshake and publication. If the implementation also changes required manager messages, bump the affected protocol and verify existing two-player sessions with spectators disabled. Keep spectator work independent of any future saved-match loading.

- [ ] Add dedicated `OnlineSpectators` feature tests and a short checklist. EditMode cases cover invite validation, full and duplicate admission, identity/role isolation, stale messages, and exclusion of private fields from encoded snapshots. Send disallowed commands through the actual host dispatch path and assert they have no match effects.
- [ ] PlayMode cases cover late join into a live Room, correct public state and final result, camera and inspection, viewer disconnect and resync, host closing watching, and repeated join/leave. Assert that manager commands and timers continue without interruption throughout. Preserve the two-manager flow with viewing disabled.
- [ ] Run the focused Unity tests under [AGENTS.md](../../AGENTS.md). Record compilation separately from passed, failed and skipped counts. Retain native XML and progress under `TestResults/GameplayRegression/Runs/`.
- [ ] Run packaged Windows and macOS clients with two managers and one viewer, then repeat at the spectator cap. Exercise cross-network joins, direct and relay paths where available, a slow viewer, disconnect and rejoin, and clean shutdown. Compare manager command latency, host frame time and outbound traffic with zero viewers and at the cap. Base any cap increase on those measurements.
